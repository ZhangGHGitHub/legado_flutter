# Legado 重写行为约束规范

## 1. 规范目的

本文档是 `Jingshiro/legado` 重写为 Rust + Flutter 过程中的行为兼容性规范。

目标不是重新设计业务行为，而是在更换技术栈后保持原版 App 的数据、规则、交互、排版和网络行为一致。

本文档中的“原版”指 `Jingshiro/legado` 当前基准版本。任何无法证明与原版一致的实现，都不得视为兼容实现。

## 2. 约束等级

以下条款均为硬性约束，优先级高于代码简化、架构偏好、性能优化和 UI 重构。

如果新平台能力与原版行为发生冲突，必须优先保持原版行为，并记录平台适配边界。

任何违反硬性约束的修改，必须在变更说明中主动标记，说明：

- 违反的条款编号
- 受影响的功能和数据范围
- 与原版不同的具体行为
- 影响原因
- 是否存在兼容迁移方案
- 后续修复计划或接受该偏差的明确理由

## 3. 书源 JSON 和规则兼容

### 3.1 JSON 格式

所有现有书源 JSON 必须 100% 兼容，包括但不限于：

- 字段名称
- 字段类型
- 字段缺省值
- `null`、空字符串和缺失字段的区别
- 嵌套对象结构
- 数组结构
- 字段大小写
- 旧版本字段和兼容字段
- 书源导入、导出和订阅格式

不得通过重命名、扁平化、类型收窄或删除旧字段来简化模型。

### 3.2 规则字段语义

以下规则的语义必须与原版一致：

- 搜索规则
- 发现规则
- 书籍详情规则
- 目录规则
- 正文规则
- 段评规则
- URL 参数规则
- JavaScript 规则
- CSS/JSoup 规则
- XPath 规则
- JSONPath 规则
- 正则和替换规则

兼容性必须覆盖：

- 规则链执行顺序
- 变量写入和读取时机
- `put` 变量作用域
- 规则中的相对 URL 解析
- 多值结果和空结果处理
- HTML 文本与属性提取差异
- JSON 对象、数组和标量转换行为
- JS 返回值转换行为
- 分页规则和下一页 URL 规则
- `preUpdateJs`、`loginCheckJs`、`webJs` 等脚本的执行时机

新增规则能力可以扩展，但不得改变已有规则的解释结果。

### 3.3 书源兼容验收

至少必须具备以下对比结果：

- 相同书源 JSON 的搜索结果字段一致
- 相同书源 JSON 的发现结果字段一致
- 相同书源 JSON 的书籍详情字段一致
- 相同书源 JSON 的目录章节数量、标题和 URL 一致
- 相同书源 JSON 的正文清洗结果一致
- 规则异常、空值、超时和登录失败结果一致

## 4. 数据库和无损迁移

### 4.1 Schema 兼容

本地数据库必须支持从原版 App 无损迁移。

以下内容不得改变：

- 数据库文件语义
- 所有表名
- 所有列名
- 主键和联合主键
- 外键关系
- 索引名称和索引语义
- 唯一约束
- 默认值
- NULL 约束
- 数据类型可表达范围
- Room 版本迁移后的有效数据

核心表包括：

- `books`
- `book_sources`
- `chapters`
- `book_groups`
- `searchBooks`
- `caches`
- `cookies`
- `bookmarks`
- `readRecord`
- `detailedReadRecords`
- `replaceRules`
- `book_thoughts`

扩展表、RSS 表、订阅表、字典规则表、TTS 表、服务器表和键盘辅助表也属于迁移范围，不得只迁移核心书架数据。

### 4.2 无损要求

迁移前后的以下数据必须逐字段一致：

- 书籍元数据
- 书籍类型位掩码
- 书架分组位掩码
- 手动排序值
- 当前章节索引
- 当前章节位置
- 阅读配置
- 自定义变量
- 书源嵌套规则
- 章节元数据
- Cookie 和缓存
- 书签、想法和阅读记录

任何未知字段、未来字段或扩展字段都必须保留，不能在迁移过程中丢弃。

### 4.3 迁移验收

迁移测试必须覆盖：

- 原版数据库直接导入
- 多次重复导入
- 中断后继续导入
- 空数据库导入
- 大量书籍、章节和缓存导入
- 含 NULL、空字符串和默认值的数据导入
- 导入后在 Rust + Flutter 中继续写入并重新导出

## 5. 文本分页完全一致

### 5.1 硬性目标

在以下条件完全相同的情况下，重写版的分页结果必须与原版 App 完全一致：

- 字体文件
- 字体版本
- 字号
- 字重
- 字体缩放
- 屏幕宽度和高度
- 内容区域边距
- 行高
- 段间距
- 字间距
- 系统 DPI
- 文本内容
- 文本清洗结果
- 分页模式

要求逐页对比，不能只比较总页数或大致视觉效果。

### 5.2 必须保持一致的排版行为

- 中文标点禁则
- 中文、英文和数字混排断行
- 连续 URL 和长字符串处理
- 段落换行
- 空行保留
- 首行缩进
- 标题和正文的间距
- 图片、音频和特殊标签占位
- 章节尾部和章节开头拼接规则
- 当前字符位置到页码的映射
- 长按选区到正文字符位置的映射

如果 Flutter 原生文本布局无法提供原版所需的分页结果，必须增加兼容排版层，不得直接接受分页偏差。

### 5.3 排版验收

验收必须保存原版和重写版的：

- 每页文本内容
- 每页起始字符位置
- 每页结束字符位置
- 总页数
- 章节边界
- 固定测试字体下的截图

## 6. 书架排序和分组

书架书籍排序、分组和筛选逻辑必须保持不变。

必须兼容：

- 手动排序值 `order`
- 最近阅读时间排序
- 书籍来源排序
- 用户分组位掩码
- 系统分组
- 本地、网络、音频、视频和错误分组
- 分组显示状态
- 分组刷新开关
- 只更新已读书籍
- 未分组书籍处理
- 书籍删除和分组删除后的位掩码变化
- 书源切换后的排序和分组迁移

不得使用新的字符串分组模型替代原版位掩码语义，除非能够保证双向无损转换。

## 7. 发现页分页和刷新

发现页的上拉加载、下拉刷新和分页状态机必须保持不变。

必须保持：

- 首次加载行为
- 下拉刷新是否重置页码
- 上拉加载的下一页计算
- 加载中时重复触发的处理
- 空结果处理
- 网络失败后的页码状态
- 取消加载后的状态恢复
- 书源分组和分类筛选状态
- 结果去重规则
- 下一页 URL 的保存和使用
- 刷新后原有列表是否保留

刷新和加载更多不得因为 Flutter Widget 生命周期变化而重复请求、跳过页码或覆盖新结果。

## 8. 阅读页手势系统

阅读页的手势行为必须保持一致。

### 8.1 点击区域

必须保持原版九宫格点击区域及其边界，包括：

- 左上、上中、右上
- 左中、中间、右中
- 左下、下中、右下

点击区域边界、系统手势区域避让和点击优先级不得改变。

### 8.2 滑动翻页

必须保持：

- 横向和纵向手势识别阈值
- 触摸 slop
- 翻页方向判定
- 取消滑动条件
- 章节边界行为
- 不同翻页动画的完成条件
- 自动阅读与手势冲突处理
- 文本选择与滑动翻页的优先级

### 8.3 菜单调出

必须保持单击、长按、文本选择和菜单调出的条件及顺序，包括：

- 单击调出操作菜单
- 长按选择文本
- 选择文本后的上下文菜单
- 中间区域点击行为
- 点击章节列表、搜索、书签和设置的入口
- 菜单打开时系统 UI 的变化

## 9. 网络缓存、重试和 Cookie

所有网络请求的缓存、重试和 Cookie 策略必须保持不变。

### 9.1 缓存

必须保持：

- 缓存键生成规则
- 缓存作用域
- 缓存优先级
- 有效期和过期判断
- 正文文件缓存路径语义
- 图片缓存策略
- 规则变量缓存策略
- 登录头缓存策略
- 空正文和失败正文是否允许写入缓存
- 缓存清理条件

### 9.2 重试和限速

必须保持：

- 重试次数
- 重试间隔
- 超时时间
- 网络异常分类
- 书源并发限制
- 单书源限速
- 请求取消行为
- 分页请求失败后的恢复行为

性能优化不得改变请求次数、请求顺序和限速语义。

### 9.3 Cookie 和登录状态

必须保持：

- Cookie 作用域
- Cookie 优先级
- 临时 Cookie 与持久 Cookie 的合并规则
- CookieJar 是否启用
- 登录检测脚本执行时机
- 登录头写回缓存的时机
- 书源切换时 Cookie 是否隔离
- Cookie 清理条件

## 10. 变更和验收规则

任何涉及以下模块的修改，都必须先进行行为影响分析：

- 书源模型或规则解析器
- 网络请求层
- Cookie、缓存和登录逻辑
- 数据库模型或迁移
- 书籍和章节模型
- 阅读器文本布局
- 翻页控制器
- 书架 Provider 或排序逻辑
- 发现页和搜索页状态机

每次变更至少需要说明：

- 影响的约束条款
- 原版行为基线
- 新版行为结果
- 对比测试方式
- 是否存在已知偏差

以下情况不得合并为完成状态：

- 只通过编译但没有行为对比
- 只比较页面截图但没有数据和分页位置对比
- 只迁移部分数据库表
- 使用“近似兼容”替代明确兼容
- 发现规则差异但未主动记录
- 以平台限制为理由静默改变行为

## 11. 偏差报告格式

发现行为不一致时，必须主动提交以下信息：

```text
约束编号：
功能模块：
原版行为：
重写版行为：
差异表现：
影响范围：
复现条件：
根因判断：
临时规避方案：
最终修复计划：
```

## 12. 规范结论

Rust + Flutter 只允许替换实现技术，不允许未经声明地替换业务语义。

书源 JSON、数据库 schema、文本分页、书架状态、发现页状态机、阅读手势和网络策略均属于兼容性基线。任何优化、重构或抽象都必须在不改变这些基线的前提下进行。
