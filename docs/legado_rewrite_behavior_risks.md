# Legado Rust + Flutter 重写行为一致性风险清单

## 文档目的

本文档记录 Legado 从 Android/Kotlin 重写为 Rust + Flutter 时，最容易出现行为不一致的技术点。

风险排序综合考虑影响范围、问题隐蔽性和真实书源覆盖面。

## 十大风险点

### 1. 书源规则解析顺序

涉及模块：`AnalyzeRule`、CSS/JSoup、XPath、JSONPath、正则、规则链。

书源规则中的变量写入、JavaScript、节点提取、字段转换和正则替换存在前后依赖。特别是 `put` 变量、规则链和嵌套 JS，不能只保证每种语法可解析，还必须保证执行顺序一致。

可能影响：

- 书名、作者或封面为空
- 目录和正文解析结果不同
- 同一规则在不同书源上产生不同结果
- 规则调试页显示成功，但实际阅读失败

### 2. `AnalyzeUrl` 请求语义

涉及模块：URL 模板、请求方法、分页参数、请求头、Cookie、重定向、字符集、WebView。

原应用的 URL 不是简单字符串，而是包含请求方法、请求体、Header、Cookie、JS、WebView、超时、重试和编码等行为的请求描述。Rust 网络层若只复刻 URL 拼接，无法保证兼容性。

可能影响：

- 搜索失败或只能打开站点首页
- POST 书源变成 GET
- 登录状态丢失
- 重定向后相对地址解析错误
- 中文或非 UTF-8 站点出现乱码

### 3. Rhino JavaScript 兼容性

涉及模块：`modules/rhino`、`AnalyzeRule`、`AnalyzeUrl`、Cookie、缓存、加解密和宿主对象。

大量书源 JS 依赖 `java.ajax`、`cache`、Cookie、书源对象、章节对象和加解密 API。Rust JS 引擎即使能执行标准 JavaScript，也必须兼容这些宿主能力和返回值类型。

可能影响：

- 登录检测失败
- 目录或正文依赖的 JS 变量没有写入
- AES、Base64 等解密规则失败
- JS 返回字符串、数组、对象时类型行为不一致
- 同一个 JS 在 Android 和新客户端结果不同

### 4. HTML、JSON 和 XPath 解析兼容性

涉及模块：JSoup、CSS 选择器、XPath、JSONPath、HTML 清洗、相对 URL 拼接。

解析器的容错行为通常比语法本身更重要。空节点、非法 HTML、文本节点、属性节点、数组路径和嵌套对象的处理差异，都会改变最终结果。

可能影响：

- 结果条目数量变化
- 章节标题或正文内容缺失
- 图片、封面和章节链接变成相对地址
- 非标准 HTML 在新客户端无法解析

### 5. 搜索并发与结果合并

涉及模块：`SearchModel`、书源筛选、并发池、超时、精确搜索、结果排序和去重。

原应用会并发访问多个书源，并根据来源顺序、权重、响应时间和精确搜索条件合并结果。并发实现不只是性能问题，也会影响结果顺序和最终展示内容。

可能影响：

- 搜索结果顺序不一致
- 同一本书出现多个重复条目
- 精确搜索误收或漏收
- 慢书源阻塞首屏
- 取消搜索后仍有旧任务回写结果

### 6. 目录分页与章节去重

涉及模块：`WebBook`、`BookChapterList`、`TocRule`、`nextTocUrl`、章节 URL 规范化。

目录可能包含多页、卷节点、重复章节、空链接和循环分页。必须保持下一页判断、访问去重、章节去重和卷节点处理的一致性。

可能影响：

- 目录缺章或重复
- 卷标题被当成正文章节
- 分页请求无限循环
- 章节顺序错误
- 阅读进度无法定位到正确章节

### 7. 正文处理流水线

涉及模块：`BookContent`、`ContentProcessor`、替换规则、标题去重、重新分段、图片和下一页正文。

正文获取后仍需进行 HTML 清理、正文替换、标题去重、重新分段、图片处理和分页正文拼接。处理顺序改变会改变实际文本，而不仅是显示样式。

可能影响：

- 正文重复或缺段
- 章节标题重复
- 替换规则结果不同
- 字数统计和阅读统计不同
- 正文分页位置发生变化

### 8. 中文排版与分页算法

涉及模块：`ReadView`、`PageView`、`ContentTextView`、`PageDelegate`、字体和排版配置。

阅读器分页依赖字体实际测量、全角标点、中文禁则断行、连续英文和数字、段落间距、行高、边距及系统 DPI。Flutter 文本布局即使视觉上相似，也不代表页边界一致。

可能影响：

- 同一章节页数不同
- 章节内位置无法精确恢复
- 进度跳转偏移
- 长按选择文本范围不一致
- 翻页动画触发章节切换的时机不同

### 9. 目录刷新后的阅读进度迁移

涉及模块：`BookHelp.getDurChapter`、`BookProgress`、章节标题匹配和书源切换。

目录更新后，章节可能新增、删除、重命名、合卷或重新排序。只保存章节索引是不可靠的，需要结合旧章节标题、章节编号、旧目录规模和新目录邻近范围迁移位置。

可能影响：

- 更新目录后跳到错误章节
- 换源后阅读位置丢失
- 章节内字符位置被错误复用
- 模拟阅读和未读数量错误

### 10. 缓存、阅读记录与同步一致性

涉及模块：章节文件缓存、`CacheDao`、`BookDao`、`ReadRecordDao`、书签、想法和远程同步。

章节正文文件、章节元数据、阅读进度、阅读记录和同步状态分布在不同存储对象中。迁移时如果缺少统一的版本、时间戳和冲突策略，容易出现部分成功、旧数据覆盖新数据或进度回退。

可能影响：

- 正文文件存在但数据库状态显示未下载
- 数据库标记已缓存但正文文件不存在
- 阅读进度被旧设备覆盖
- 阅读记录重复累计或丢失
- 书签和想法无法关联到正确书籍

## 优先验证范围

以下四类问题应优先建立跨平台兼容性测试：

1. 规则解析顺序和 JS 宿主 API
2. 目录分页、章节身份和章节去重
3. 正文处理顺序和中文分页
4. 进度迁移、缓存一致性和同步冲突

## 验证方式

行为一致性不应只依赖单元测试，建议同时使用：

- 固定网络响应的书源回放测试
- Android 与 Rust 解析结果字段对比
- 目录章节数量、标题和 URL 快照对比
- 正文清洗前后文本对比
- 固定字体和屏幕尺寸下的分页快照对比
- 阅读进度迁移前后章节和字符位置对比
- 缓存异常、断网、取消请求和并发切换测试
